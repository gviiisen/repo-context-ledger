# Reusing the global runtime

Default repositories keep a standalone bundled runtime. On a workstation that explicitly chooses a single globally installed Codex Skill, `init --runtime global --dry-run` previews a normal initialization with a small forwarding entry; the corresponding init applies it. Review all planned writes first. Existing `runtime.mode` is preserved by subsequent init calls; `--runtime bundled` explicitly restores a bundled copy.

The saved setting is `"runtime": {"mode": "global"}` in `.context-ledger/config.json`. The project entry `.context-ledger/ledger.py` resolves `CODEX_HOME/skills/repo-context-ledger/scripts/ledger.py`, or the user's `.codex/skills` when CODEX_HOME is unset. No user-specific absolute path is committed. CODEX_HOME must be absolute; a missing target or a target inside the calling repository fails closed, without downloading or falling back to an old runtime. Other editors can use the same entry on this machine if that global installation exists; a fresh clone/CI machine must install it or choose bundled mode.

The forwarding entry supplies its own repository root even when invoked from another directory; an explicit global `--repo` argument still takes precedence. Global updates take effect on the next command. This shares executable code, not repository configuration, presets, permissions, principal identity, drafts, caches, or completed history. Agents must still reload updated Skill instructions in a new turn/window; updating a file does not rewrite already-loaded conversation context.

For a mature repository that must keep all documentation and task state unchanged, avoid an unrestricted init merely to replace the runtime. Back up the existing installation outside skill-discovery directories. Update only the runtime mode, forwarding entry, and reviewed Agent entry instructions, preserving configuration values and all history/state. Remove a project-local Skill directory only after confirming that it actually is a duplicate Skill, not `.context-ledger` configuration or documentation. A stale instruction that actively requires a shared active-handoff pointer must be explicitly retired during migration; leave the historical pointer and records themselves intact.

Verify forwarding with `--version`, read-only status, and adapter checks. Compare the existing documentation and state before/after, and do not commit the consuming project unless requested. Global mode is intentionally opt-in: a pinned bundled version remains useful for CI and collaborators who do not share this workstation.
