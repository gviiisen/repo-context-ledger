## Intent

将并发任务的未完成 handoff 从正式历史迁移到各自的 Git 私有 session draft，并在验证通过后原子归档。完成标准是多个任务只写自己的草稿、`docs/changes/` 只出现 completed change、归档失败可重试且不会重复或删除其他 session，同时 Ledger 不接管源码复制、锁定或合并。

## Changed behavior

Before: v0.5.2 虽然按 Session ID 隔离多个 active handoff，但 `start` 立即在 `docs/changes/` 创建未完成 Markdown；这些草稿会污染 Git 状态和正式历史。归档前后的失败边界也没有区分私有草稿与已发布记录。

After: v0.5.3 将 active/paused 内容保存在 worktree Git 元数据的 `sessions/<id>/handoff.md`，state 预留唯一 `publish_path`。`finish` 验证草稿后原子发布 completed change，更新链接与派生内容，通过检查后只清理该 session；中断重试按 Session ID 幂等恢复。

## Boundaries and risks

- Invariant: 未完成 handoff 不进入 `docs/changes/`；一个 draft 只属于一个 Session ID；歧义命令拒绝猜测；成功 finish 只发布一次并只清理当前 session。
- Failure / recovery: 验证或发布后检查失败时保留私有 draft 和 session；若 completed target 已由同一 Session ID 写入，重试复用该记录并重新执行链接、同步和检查，不重复创建历史。
- Not changed: 不复制源码、不创建 worktree、不认领路径、不锁定或合并代码，也不替 Codex/Git 处理代码冲突；禁止未经用户授权联系或中断其他任务的规则继续保留。
