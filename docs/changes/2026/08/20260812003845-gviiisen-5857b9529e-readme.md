## Intent

修正 v0.5.1 自举检查发现的 README 误分类，确保双语根 README 与配置模块 README 不会被当成生产实现并错误要求 Context Pack。验收结果是仓库自身的严格 Coverage 能识别所有受管 README，且完整回归测试保持通过。

## Changed behavior

Before: `coverage_path_kind` 只把根 `README.md` 视为受管文件，`README.zh-CN.md` 和模块 `README.md` 会落入 implementation 兜底，导致无关联 Pack 错误。

After: 根目录符合 `README(?:\.[^/]+)*\.md` 的文件和 `config.modules[*].readme` 都返回 managed，翻译 README 与模块摘要不再触发生产行为 Coverage。

| `tests/test_ledger.py` / `test_coverage_classifies_tests_ci_config_and_managed_paths` | 路径分类回归。 | 新增 `README.zh-CN.md` 与 `apps/api/README.md` 的 managed 断言。 |

## Boundaries and risks

- Invariant: 只有根目录 README 变体和配置中明确登记的模块 README 被特殊处理，任意子目录 Markdown 不会因此自动排除。
- Failure / recovery: 模块 README 未登记时仍按普通 glob 分类；重新运行 `init` 可刷新模块发现与配置，再执行 Coverage 检查。
- Not changed: Context Pack 精确 tracked-file 关联、glob 优先级、handoff/spec 要求及 Agent adapter 行为均未改变。
