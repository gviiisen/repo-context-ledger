## Intent

修复同一 worktree 多个 Codex 任务互相抢占 active handoff、长时间验证独占 Ledger 写锁，以及 Agent 未经用户授权向其他任务发送协调消息的问题。完成标准是多个任务会话可并存且只能显式操作自身会话，外部验证运行期间其他会话仍可写入，生成的跨 Agent 指令明确禁止主动干预其他用户任务。

## Changed behavior

Before: 私有状态只有一个 `active_handoff` 和一组 `paused_handoffs`；新任务必须暂停或覆盖当前任务。`verify` 在外部命令整个运行期间持有 `.write.lock`，其他会话无法更新记录。Agent 指令没有禁止主动联系另一个正在执行的用户任务。

After: v6 私有状态按 Handoff ID 保存多个 active/paused task session；有多个候选时生命周期命令必须传 `--session`，否则确定性拒绝。`verify` 仅在绑定目标和写回结果时短暂持锁。Skill 与所有原生 adapter 禁止未经用户授权的跨任务消息、委派、引导和中断。

## Boundaries and risks

- Invariant: 一个 handoff 最多属于一个 task session；生命周期操作不会在多个候选中猜测；finish 只删除被选中的 session；历史 change 原文不会因状态迁移被批量重写。
- Failure / recovery: 验证运行期间目标 session 被暂停、完成、删除或重新绑定时，结果拒绝写入而不是落到别的 handoff；调用方可针对当前 session 重新运行验证。
- Not changed: task session 只隔离 Ledger 账本，不合并并发代码编辑，也无法从运行时阻止 Codex 应用层消息；相同代码路径仍需独立 worktree 或用户明确协调。
