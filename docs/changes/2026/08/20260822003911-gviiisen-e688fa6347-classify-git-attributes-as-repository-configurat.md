## Intent

Classify Git attribute policy as repository configuration so a branch that adds `.gitattributes` can pass strict changed-scope Coverage without inventing implementation evidence. Acceptance requires the path classifier, initialized configuration, generated standalone runtimes, and regression test to agree that `.gitattributes` is configuration.

## Changed behavior

Before: The default Coverage glob policy did not name `.gitattributes`, so the catch-all implementation glob classified it as production behavior. A legitimate line-ending policy fix therefore failed strict Coverage with an unrelated missing-handoff error for `.gitattributes`.

After: Default and repository-local Coverage configuration classify `.gitattributes` as `config`. Strict changed-scope Coverage still checks implementation paths, while checkout policy changes no longer require an implementation handoff merely to satisfy the catch-all glob.

## Boundaries and risks

- Invariant: The explicit test, CI, config, generated, managed, and ignored classifications continue to take precedence over the catch-all implementation glob.
- Failure / recovery: A user can still override `coverage.config_globs`; invalid or missing configuration retains the existing deterministic validation and migration behavior.
- Not changed: This does not exempt source files from Coverage, alter Git line-ending semantics, or weaken handoff-to-evidence intersection rules.
