## Intent

Fix the Windows GitHub Actions runtime drift found on PR #12. Acceptance requires a fresh checkout with `core.autocrlf=true` to preserve canonical generation inputs and both generated runtime outputs as LF, so the same byte-level build check passes on Windows and Unix.

## Changed behavior

Before: the repository had no `.gitattributes`; Windows checkout converted tracked generated Python files to CRLF while the builder emitted LF, so `python scripts/build_runtime.py --check` failed before tests.

After: repository attributes pin the runtime-generation chain to LF. A focused Git-attribute regression test covers the exact inputs and outputs, while the existing byte-identity and drift tests remain green.

## Code paths

| Path / symbol | Responsibility | Actual change |
| --- | --- | --- |
| `.gitattributes` | Controls checkout normalization for deterministic runtime generation. | Pins the builder, template, fragments, and both generated runtime artifacts to `eol=lf`. |
| `tests/test_runtime_build.py::test_git_checkout_pins_runtime_generation_inputs_and_outputs_to_lf` | Protects the Windows checkout boundary. | Uses `git check-attr` to fail when any generation input/output loses the LF contract. |
| `ARCHITECTURE.md` | Documents canonical-source build behavior. | Records why byte comparison requires Git-level LF normalization. |

## Boundaries and risks

- Invariant: generated Skill and dogfood runtimes remain byte-identical standalone files; users still receive one zero-dependency runtime.
- Failure / recovery: CI fails immediately when checkout attributes or generated bytes drift; repair `.gitattributes` or canonical source and rebuild rather than editing one output.
- Not changed: Runtime behavior, CLI schemas, Python support, and `init` distribution are unchanged.
